## 一句话:它是什么?

Alfred 是一个 **AI 私人助理(相当于给你配了个"办公室大管家")**。

你把 Gmail 和 Google 日历连上它(也能接短信和 WhatsApp),它就会:

- 帮你**读**所有新邮件,
- **挑出**真正重要的事、你答应过别人的事、你的待办,
- 帮你**起草**回复,
- 甚至能帮你**发邮件、加日程**——

但有一条铁律:**任何会影响到外部世界的动作(比如替你发信、花钱),它都会先给你看草稿、等你点"同意"才做**,绝不擅自行动。

> 打个比方:它像一个很勤快、很聪明的助理,会把信读完、把回复写好、把日程排好,
> 然后拿到你面前说"我准备这么做,可以吗?"——你点头,它才动手。

**重要且诚实的一点:** 它**不是**那种"自己想干嘛干嘛"的 AI。它是一个**按固定流程办事、
遇到有风险的事一定叫你拍板**的助理。这其实是它最大的卖点:**安全、可信**。

## 一、用了什么工具(以及为什么用它)

下面每一个技术,都配了一句"人话解释"和"为什么选它"。

### 后端(服务器这一侧,也就是"大脑")

| 工具 | 人话解释 | 为什么用它 |
|---|---|---|
| **Python + FastAPI** | 写服务器程序的语言和框架,负责接收请求、处理逻辑 | Python 写 AI 相关的东西最顺手;FastAPI 快且简单 |
| **Celery** | 一个"定时工",能在后台按时间自动干活(比如每隔几分钟去查一次你的收件箱) | 你不用一直盯着,它自己定时跑 |
| **Postgres** | 数据库,长期存东西的地方(像一个大文件柜) | 稳定、可靠、行业标准 |
| **Redis** | 超快的"临时记忆",还能当"锁"防止两个任务同时抢一件事 | 快;而且能防止"同一封邮件被处理两遍" |

### AI(负责"看懂"和"写字")

| 工具 | 人话解释 | 为什么用它 |
|---|---|---|
| **Anthropic Claude** | 一个大语言模型,只干两件事:**读懂邮件** + **起草文字** | 只在这两步用 AI,而且是"让它照着固定表格填空",不让它乱做主 |

> 关键设计:AI 在这里**没有"动手"的权力**。它只能"读"和"写草稿",
> 真正发出去、改日历这些动作,都要走后面说的审批闸门。

### 手机 App(用户看到、点的那一面)

| 工具 | 人话解释 | 为什么用它 |
|---|---|---|
| **Expo / React Native** | 一套代码,同时能生成 iPhone 和安卓 App | 不用写两遍,省一半功夫 |
| **React Query** | 让 App 里的数据自动保持最新(你一操作,画面就刷新) | 用户永远看到最新状态,不会看到过期数据 |

### 安全和运维(保证"不出事、出事能查")

| 工具 | 人话解释 | 为什么用它 |
|---|---|---|
| **令牌加密 + 换钥匙** | 你的 Gmail 授权凭证是**加密存的**,而且能在不影响老数据的情况下换密钥 | 就像换门锁不用把旧钥匙全作废——安全又不折腾 |
| **可即时吊销的登录** | 登录凭证能**一秒作废**(比如手机丢了) | 出事能马上切断,不用等它自然过期 |
| **Sentry** | 出错时自动记录、报警 | 有 bug 能第一时间知道 |
| **Prometheus** | 记录各种运行指标(花了多少钱、快不快) | 花销和性能一目了然 |
| **日志脱敏** | 记录日志时**自动抹掉个人隐私**(邮箱、电话、密钥等) | 就算日志被人看到,也看不到用户的私密信息 |

## 二、实现了什么(用户能真实体验到的功能)

- **一个安静的"今日" (Today) 首页。** 打开 App,看到的不是一堆乱糟糟的邮件,
  而是"今天真正该处理的几件事"。
- **自动挑出"你答应过别人的事"。** 它能从邮件里读出"你说过下周给对方发合同"这种承诺,
  免得你忘了。
- **每件事都告诉你"为什么重要"。** 不是干巴巴写个"高优先级",而是写清楚原因:
  "今天到期,而且对方在等你回复"。
- **帮你写好回复草稿。** 你只需要看一眼、改改、点发送。
- **有风险的动作先问你。** 发邮件、改日程、花钱之前,一定弹出来让你确认。
- **会主动提醒你。** 比如"这个人 3 天没回你了",并**顺手把追问邮件的草稿写好**等你批准;
  开会前还能帮你准备一份简报。
- **所有做过的动作都有记录。** 谁、什么时候、做了什么,全记在案(审计日志)。

## 三、Workflow:跟着一封邮件走一遍(它到底怎么工作)

我们跟着**一封新邮件**从进来到处理完,看看每一步发生了什么:

1. **触发。** 要么是定时工 Celery 每隔几分钟自动检查,要么是你手动点"同步"。
2. **收取。** 它去你的 Gmail / 日历拉回新的内容。
   （只存邮件的**摘要和基本信息**,**不存邮件全文**——存得越少,万一泄露损失越小。)
3. **读懂 (AI)。** Claude 读这封邮件,给它打标签,并**抽出里面的承诺和待办**
   （比如"周五前把报价发过去")。
4. **排序(这一步是固定规则,不是 AI)。** 一个**透明的打分程序**给每件事打 0–100 分,
   排出轻重缓急。**因为是死规则,所以永远能解释清楚为什么这件事排在前面**,
   不会出现"AI 说重要但没人知道为啥"的情况。
5. **准备提案。** 对需要动手的事(比如回封信),它**先写好一份草稿方案**,但不发。
6. **给你看。** 把草稿方案摆到你面前。
7. **你批准。** 你点"同意"。
8. **执行。** **只有在这一步之后**,它才真的把邮件发出去 / 把日程加上。
9. **记录。** 这次动作被写进审计日志,永久留痕。

> 核心就一句:**AI 负责"读"和"写草稿",人负责"拍板",程序负责"记录"。**
> 越往后越危险的动作,越要你点头。

## 四、架构:它长什么样(配图 + 大白话)

```
   ┌─────────────┐      ┌──────────────┐      ┌────────────────────┐
   │   手机 App   │ ⇄   │   API 服务器  │ ⇄   │   后台定时工        │
   │ (你看和点的) │      │  (总调度/大脑) │      │ (Celery, 定时干活)  │
   └─────────────┘      └───────┬──────┘      └─────────┬──────────┘
                                │                        │
                                ▼                        ▼
                    ┌───────────────────────────────────────────┐
                    │   数据库(长期存) · 快速缓存 · AI(读/写)   │
                    └───────────────────────────────────────────┘

   ★ 所有"要在现实世界动手"的动作(发信/花钱/改日程),
     都必须先经过同一道【审批闸门】—— 你不点头,它就过不去。
```

每个部分用生活化的比喻解释:

- **手机 App = 前台窗口。** 你看到的、点的都在这;它自己不做决定,只负责显示和收指令。
- **API 服务器 = 大脑 / 总台。** 收到请求后,决定叫谁去干活、把结果整理好返回。
- **后台定时工 (Celery) = 不用人催的勤杂工。** 按时间自动跑:定时查收件箱、发提醒、做简报。
- **数据库 = 大文件柜。** 长期存用户、邮件摘要、承诺、待办、动作记录等。
- **快速缓存 (Redis) = 便利贴 + 门锁。** 存临时的东西,还负责"锁门"防止两个任务撞车。
- **AI (Claude) = 会读会写的秘书。** 只在"读懂邮件、起草文字"两步出现,没有动手权。
- **审批闸门 = 保安 + 你的签字。** 所有危险动作都得从这道门过,你签字才放行,并留下记录。

> 为什么这样设计好?因为**安全规则只写在这一道门里**。以后加任何新功能(比如接微信),
> 它自动就享受同样的"要审批、有花销上限、留记录"保护,不用每个功能重新写一遍(也就不会写错)。

### 2) 简历要点(英文,每条附中文说明)

> 都是基于真实代码,可以在面试里展开。用之前把 `[X]` 换成你测到的真实数字。

- **Built an AI assistant that reads Gmail/Calendar, extracts commitments and to-dos, and
  surfaces a ranked "Today" view** — using a Python/FastAPI backend with Celery background
  jobs, Postgres, and Redis.
  *中文:做了一个 AI 助理,读邮件和日历、抽出承诺和待办、排出"今日"清单;后端用 Python/FastAPI
  + Celery 定时任务 + Postgres + Redis。*

- **Designed a human-in-the-loop "approval gate" so no external action (send email, calendar
  change, payment) ever runs without explicit user approval, with spend limits and a full
  audit log.**
  *中文:设计了一个"人来拍板"的审批闸门——发邮件、改日程、付款等外部动作,不经用户批准绝不执行,
  还带花销上限和完整审计记录。*

- **Used the LLM in a controlled, structured way** — the AI only classifies and drafts by
  filling a fixed schema (forced tool-use), never runs free-form commands, which also blunts
  prompt-injection risk.
  *中文:以受控、结构化的方式使用大模型——AI 只按固定表格"填空"来分类和起草,不执行自由指令,
  也顺带降低了"提示注入"攻击的风险。*

- **Kept ranking explainable by making priority a deterministic rules engine (not the LLM)**,
  so every surfaced item shows a plain-English reason like "due today, and Chaker is waiting
  on you."
  *中文:把"重要性排序"做成固定规则(不用 AI),所以每件事都能给出大白话理由,
  比如"今天到期,而且对方在等你"。*

- **Encrypted OAuth tokens at rest with zero-downtime key rotation**, and added instantly
  revocable login sessions for security.
  *中文:把 Google 授权令牌加密存储,并支持零停机换密钥;登录会话可即时吊销。*

- **Shipped a cross-platform mobile app (Expo / React Native) with React Query** so the UI
  always reflects the latest data after any action (mark-done, dismiss, sync).
  *中文:用 Expo / React Native 做了跨平台手机 App,配 React Query,任何操作后界面都自动刷新到最新。*

- **Added production-grade observability** — error tracking (Sentry), metrics (Prometheus),
  and PII-redacting logs that scrub emails/phones/tokens everywhere they could leak.
  *中文:加了生产级可观测性——错误追踪(Sentry)、指标(Prometheus)、以及会自动抹掉隐私
  (邮箱/电话/令牌)的日志。*

- **Prevented double-charges and duplicate work** using idempotency keys, row-level locks for
  spend limits, and a fail-open distributed lock so two jobs can't collide.
  *中文:用幂等键、花销上限的行级锁、以及分布式锁,防止重复扣款和重复干活。*

### 3) 面试怎么讲(3–4 个简单要点)

- **"这是个完整系统,不是套壳。"** 前端手机 App、后端服务器、后台定时任务、数据库、
  安全、AI 全是我自己端到端做的。
- **"最难也最值得讲的是'又主动又安全'。"** 让助理能主动帮你干活,但危险动作一定要人拍板——
  这靠一道统一的审批闸门实现。
- **"我特意不让 AI 说了算。"** 排序用死规则(能解释),AI 只负责读和写草稿,没有动手权。
- **"我很在意可靠和安全。"** 令牌加密、零停机换钥匙、防重复扣款、日志脱敏、出错必留痕。

### 4) 面不同公司,怎么侧重(每组 1–2 句)

- **Anthropic / OpenAI(AI 安全类):** 重点讲"审批闸门 + 人来拍板"是个实打实的 AI 安全设计;
  AI 只按固定结构输出、没有执行权,防提示注入。
- **Google(Gmail/日历、大规模系统):** 重点讲真实用了 Gmail/日历 API、OAuth 授权、
  只拉变化的增量同步、以及分布式系统的取舍。
- **Stripe / 金融科技类:** 重点讲金融级安全——防重复扣款、花销上限加锁、每笔操作都审计、日志脱敏。
- **产品公司(Notion / Linear / Superhuman 等):** 重点讲产品体感——安静的"今日"首页、
  能解释的优先级、贴心的提醒(免打扰时段、合并通知)、移动端流畅。

### 5) 3 分钟 Demo 大纲(简单步骤)

1. **开场(20 秒):** "这是 Alfred,一个 AI 大管家。连上 Gmail 和日历后,
   我看到的不是收件箱,而是一个清爽的'今日'。" —— 打开 Today 页面。
2. **亮点(45 秒):** 指着一条事项的**理由说明**:"它不只说'重要',还告诉你**为什么**:
   今天到期,而且这个人在等你。这是固定规则算出来的,能解释。"
3. **抽取(30 秒):** 展示从邮件里抽出的一条承诺,带原文引用。"如果我后面已经回过了,
   它会自动关掉这条,不会再烦我。"
4. **草稿(20 秒):** 点开一份写好的回复草稿。"这是它起草的——起草是内部动作,不需要批准。"
5. **安全闸门(45 秒,重点):** 点"同意发送" → 展示**审批卡片** → 落到审计记录。
   "这是核心:发送是有风险的动作,不经我同意绝不发,而且每次都留记录。
   付款还得再确认一次并受花销上限限制。"
6. **收尾(15 秒):** "所以它够主动,能帮你记住容易忘的事;又够安全,
   可以放心把邮箱和钱交给它。"

> **小提示:** 提前在演示账号里放几封真实感的邮件,让"这事儿我本来会忘"的瞬间更打动人。
