# Alfred 移动端 · UI 设计 Brief

## 你负责什么

你负责：
- 信息架构与视觉层级（哪块最重、扫一眼能否抓住重点）
- 主屏与组件外观（卡片、按钮、Pill、空态、错误态等）
- 关键帧（加载中、成功、失败、无数据）
- **Companion Avatar 的版式、尺寸、落点与表情状态故事板**（见下方「Avatar」）
- Figma 组件化与 Auto Layout
- Dev handoff 标注（字号、色值、间距、状态）

你不负责：
- 写代码 / 进 GitHub
- 后端逻辑、API、账号体系、XP / 升级数值实现
- After Effects / Lottie 工程导出（除非另行约定为动效交付）
- 自行改产品能力边界（例如加新功能入口需先对齐）
- 最终上线实现（由工程对照 Preview 落地）

合作方式：你在真机 Preview 里体验 → 在 Figma 出稿 → 工程实现 → 你再在 Preview 上验收。

---

## 目标用户

忙碌的**首席助理使用者**（或同级别、高信息密度的个人决策者）：
- 一天打开 App **几次**
- 目标是**快速处理**：看清今天最要紧的事、扫邮件、问一句、记下一条
- 不是长时间浏览、不是运营后台、不是数据看板

设计成功标准：打开后 **3 秒内知道该处理什么**；完成一次操作尽量少跳转。

---

## 设计约束（必须遵守）

1. **保留 serif / mono 层级**：标题用 serif 表达「被关照」；eyebrow / pill / meta 用 mono；正文用系统无衬线
2. **保留底部 5 Tab**：Today · Inbox · 中间 Capture · Ask · You（Settings）
3. **不要做成信息仪表盘**：禁止 stats 墙、多 KPI 条、卡片堆叠成后台感、第一屏塞满次要信息
4. **气质**：冷静、得体的管家感——温暖但不可爱过头，精致但不装饰炫技

参考视觉方向：浅色编辑杂志风（奶油纸底 + 靛蓝强调 + 陶土警示），不是暗色科技风，不是紫色渐变 SaaS。

## 现有主屏

1. **Today** — 日期 eyebrow、问候、今日优先、等人回复、小快赢、Alfred 建议
2. **Inbox** — 「What matters」、分类条、邮件卡（可展开：Alfred 解读 + 操作）
3. **Ask** — 对话气泡、建议问法、底部输入
4. **Capture**（中间 Tab）— Speak / Type / Snap / Forward；语音 idle / 录音 / 解析确认
5. **You（Settings）** — 档案、集成、偏好、审批等级、账号
6. **Sheet**：MeetingPrep、Approval（邮件草稿审批）

## Companion Avatar（管家形象 / 动画）

### 产品角色（一句话）

Alfred 的后台工作大多「看不见」。Avatar 让工作**可见、有温度**：一眼知道「他在忙 / 在想 / 搞定了」，并随使用成长（等级光环）。**化妆性装饰永远不挡功能**；不需要 onboarding。

### 现状 vs 目标

| | 现状（Preview 里能看到） | 目标（后续动效包） |
|--|--------------------------|-------------------|
| 呈现 | 静态立绘 + 表情 overlay + 轻微呼吸/浮动 | 单时间轴 Lottie，按状态播片段 |
| 你的工作 | 版式、尺寸、落点、表情帧与交互故事 | 接能动效：见下方「动效交付」；`wave`（打开 App / Today 打招呼）|

### 出现位置（设计时必须画进布局）

1. **底部中间 Tab（中心钮）** — 主落点；点击应有「在听」反馈（短暂 thinking）
2. **Today** — 问候陪伴感（可有轻量打招呼）
3. **Ask** — 请求进行中切到 thinking；成功/失败要能闪一下对应情绪

不要做成第二个聊天机器人主页；交互仍锚定**真实事务**（记下、提问、处理），不是无拘束陪聊。

### 情绪状态（必须出齐表情/pose）

| 状态 | 循环？ | 感觉 |
|------|--------|------|
| `idle` | 循环 | 平静悬浮、偶尔眨眼 |
| `focused` | 循环 | 更专注、眯眼、浮动更紧 |
| `thinking` | 循环 | 抬眼思索、节奏稍快（Ask 加载时） |
| `success` | 单次 → 回 idle | 开心弹一下 / 完成感 |
| `error` | 循环 | 低落、可有汗滴，不要夸张崩溃 |
| `sleep` | 循环 | 闭眼、变暗、慢呼吸（低频使用） |


### 气质约束

- Light Airy Butler：轻、稳、得体；动作小、短、可读  
- 不要卖萌过头、不要大型特效遮挡 Tab / 正文  
- Avatar **永不遮挡**主任务信息；失败/成功反馈服务事务结果，不抢戏  

### 你需交付（Avatar 部分）

1. Figma：各落点的尺寸、边距、与 Tab / 标题的对齐关系  
2. 上述 **6 个情绪** 的关键静态帧（可用组件变体） + `打开 App / Today 打招呼 
3. 中心 Tab 点击 → thinking → 进入 Capture/交互 的简短流程帧  

参考图由工程侧另发（设计 sheet / Preview 录屏），**不开放源码**。

### 若同时接 Lottie 动效

交付：Lottie JSON（+ 最好有 `.aep`）· 每状态预览 MP4/GIF · LottieFiles 链接  
技术要点（工程会再对口）：单时间轴分段 · 30fps · 画布 512×512 透明底 · 纯矢量 · 文件尽量 ≤200KB · 强调色图层需稳定命名以便运行时换色。

中心 Tab「小房子 / 云窝」可另做小件：`home_idle` / `home_occupied`。

## 必须覆盖的状态

每个你负责的屏，至少出齐：

| 状态 | 要求 |
|------|------|
| 空态 | 无内容时仍有方向感，不空洞到「什么都没有」 |
| 加载 | 明确在拉取，不闪白、不误触 |
| 1 条内容 | 少量内容时版面不散、不空 |
| 10+ 条内容 | 可扫读、层级清楚、不挤成仪表盘 |
| 错误 | 失败可理解、可重试（或说明下一步） |

另请顺带考虑：按压态、禁用态（按钮）。
